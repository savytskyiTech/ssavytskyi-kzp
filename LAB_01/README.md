# Лабораторна робота № 1 — Ветклініка

**Варіант 21.** Розгортання Java-проєкту та базова обробка даних.
Поточний етап: налаштування та перевірка інфраструктури на Java 21.
Стартова програма підтримує звичайний запуск, `--help` і `--version`.
Читання CSV та показники ветклініки нижче поки є планом предметної реалізації.

## Задача

Прочитати візити до ветклініки з UTF-8-файла, перевірити записи,
обчислити показники та сформувати однаковий звіт у консолі й файлі.

Формат одного рядка, без заголовка:

```text
animal;species;visitType;price;urgent
```

| Поле | Тип | Перевірка |
| --- | --- | --- |
| `animal` | `String` | Непорожнє ім'я тварини |
| `species` | `String` | Непорожній вид тварини |
| `visitType` | `String` | Непорожній тип візиту |
| `price` | `double` | Скінченне невід'ємне число, десяткова крапка |
| `urgent` | `boolean` | Рівно `true` або `false` |

У рядку має бути рівно п'ять полів. Крайові пробіли полів прибираємо.
Довідники видів і типів візиту методичкою не задані; непорожній текст допустимий.
Нульова ціна допустима. Вимога скінченності виключає `NaN` та нескінченність.
Це уточнення валідації для реалізації, а не додаткові поля варіанта.

Показники для коректних записів:

1. Кількість записів.
2. Середня вартість візиту.
3. Загальний виторг — сума вартостей візитів.
4. Кількість ургентних візитів (`urgent=true`).

За відсутності коректних записів лічильники й виторг дорівнюють нулю,
а замість середнього виводиться «немає даних».
Це обрана поведінка порожньої вибірки, яку потрібно перевірити тестом.

## Приклад даних і очікування

`data/input.csv` містить три коректні та два некоректні записи.
Усі дані синтетичні.

| Показник | Очікуване значення |
| --- | --- |
| Коректні записи | 3 |
| Середня вартість | 600.00 |
| Загальний виторг | 1800.00 |
| Ургентні візити | 1 |

Рядок 4 пропускається через порожнє ім'я, рядок 5 — через від'ємну ціну.
Програма має повідомити номер рядка й причину та продовжити обробку.
Таблиця — розраховане вручну очікування, а не результат виконання програми.

## Інтерфейс

- `--help`: довідка.
- `--version`: версія з POM і номер збірки, наприклад `1.0.0+local`.
- Поки звичайний запуск повідомляє про готовність стартової інфраструктури.
- Заплановано: вхід `data/input.csv`, вихід `output/report.txt`.
- Заплановано: `--input <path>` і `--output <path>` для власних шляхів.

## Збірка та запуск

Потрібна JDK 21. Глобальна інсталяція Maven не потрібна: Wrapper завантажує
зафіксовану Maven 3.9.11 і перевіряє її контрольну суму.
Усі команди нижче виконуються з каталогу `LAB_01/`.

Ubuntu / macOS:

```sh
./mvnw --batch-mode --no-transfer-progress clean verify
java -jar target/lab01-1.0.0-all.jar
java -jar target/lab01-1.0.0-all.jar --help
java -jar target/lab01-1.0.0-all.jar --version
```

Windows PowerShell:

```powershell
.\mvnw.cmd --batch-mode --no-transfer-progress clean verify
java -jar target/lab01-1.0.0-all.jar --help
java -jar target/lab01-1.0.0-all.jar --version
```

`verify` включає компіляцію, чотири JUnit-тести справжнього CLI,
пакування через Shade та SpotBugs. JUnit є тестовою залежністю;
поточна стартова програма не потребує сторонніх бібліотек під час запуску.

Для окремих перевірок доступні `./mvnw test` і `./mvnw package`
(у Windows замінити `./mvnw` на `.\mvnw.cmd`).

## GitHub Actions

Workflow: `.github/workflows/lab01-ci.yml`, назва **Lab 01 CI**.
Push у `main` або `codex/**` і Pull Request до `main` запускають перевірку,
якщо змінено код, дані, build-файли або сам workflow.
Зміни лише Markdown-документації не запускають повторну збірку.

Матриця: `ubuntu-latest`, `windows-latest`, `macos-latest`, Temurin JDK 21.
На кожній ОС: Maven Wrapper → `clean verify` → запуск JAR без аргументів,
з `--help` і `--version` → перевірка номера збірки.

Артефакти зберігаються 7 днів:

- `lab01-<os>-java21`: виконуваний JAR та результати його запуску;
- `lab01-reports-<os>`: звіти JUnit і SpotBugs, зокрема після помилки перевірки.

У CI ресурс версії отримує номер запуску workflow, локально — `local`.
Ручний запуск `workflow_dispatch` буде доступний через інтерфейс Actions
після додавання workflow до основної гілки `main`.

Результати запусків: [GitHub Actions](https://github.com/savytskyiTech/ssavytskyi-kzp/actions).
Зелений CI цього етапу перевіряє стартову інфраструктуру; валідацію CSV та
обчислення показників потрібно реалізувати й перевірити окремо.
