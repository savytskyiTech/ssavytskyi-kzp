# План виконання лабораторної № 1

Рівні накопичувальні. Спочатку перевіряємо рівень 2, потім додаємо рівень 3.
Кожен наведений пункт стане окремим GitHub Issue; це чернетки,
поки немає фактичних номерів Issues.

## 1. Налаштування лабораторної роботи №1 — infra

- [x] Визначити варіант 21, предметну область і формат репозиторію.
- [x] Підготувати README, чернетку REPORT і службові файли.
- [x] Підготувати правила Codex та ролі Менеджер і DevOps.
- [ ] Створити публічний `ssavytskyi-kzp` та завантажити `main` і `codex/lab-01`.
- [ ] Створити Issues та записати посилання до REPORT.
- [ ] Установити JDK 21 і перевірити `java`, `javac`, `jar`.

## 2. Відтворювана Maven-збірка — infra

- [ ] Перевірити простий Hello World засобами JDK.
- [ ] Додати POM: Java 21, UTF-8, узгоджені координати та пакет.
- [ ] Згенерувати справжній Maven Wrapper і зберегти його файли в Git.
- [ ] Підключити JUnit 5 і виконати перевірку поведінки стартової програми.
- [ ] Підключити статичний аналізатор до `verify`.
- [ ] Налаштувати виконуваний JAR із залежностями.
- [ ] Успішно виконати `test`, `verify`, `package` та запустити JAR.

## 3. Читання й валідація візитів — feature

- [x] Описати формат та додати три коректні й два хибні записи українською.
- [ ] Студент реалізує аргументи `--help`, `--input`, `--output`.
- [ ] Читання через `Path` та явне UTF-8.
- [ ] Перевірка п'яти полів, непорожніх текстів, ціни та строгого boolean.
- [ ] Пропуск хибного запису з номером і причиною; наступні записи обробляються.
- [ ] Зрозуміле повідомлення для відсутнього або нечитабельного файла.

## 4. Показники та звіт — feature

- [ ] Студент реалізує чотири показники з README.
- [ ] Читання, обчислення та форматування мають окремі методи.
- [ ] Один текст звіту для консолі й вихідного файла, UTF-8, `Locale.ROOT`.
- [ ] Приклад дає 3 / 600.00 / 1800.00 / 1.
- [ ] Порожня вибірка не спричиняє ділення на нуль.

## 5. Перевірки поведінки — feature

- [ ] JUnit: валідний приклад, порожній файл, усі записи хибні.
- [ ] Некоректне число, від'ємна ціна, `NaN`, нескінченність, ціна 0.
- [ ] Строгий boolean, порожні поля, неправильна кількість полів.
- [ ] Український текст, LF/CRLF, шлях із пробілами.
- [ ] Відсутній вхідний файл та недоступний вихідний шлях.
- [ ] Реальні дефекти оформлено як `bug` Issues; виправлення пов'язано з ними.

## 6. Документація та здача рівня 2 — docs

- [ ] README містить перевірені команди й фактичний приклад роботи.
- [ ] Javadoc для публічного класу, main і нетривіальних методів.
- [ ] REPORT: результати, Issues, коміти, PR і фактичний внесок Codex.
- [ ] Студент відповідає на контрольні питання та пояснює власний код.
- [ ] PR із `codex/lab-01` до `main` закриває реальні Issues через `Closes #N`.
- [ ] Окремий звіт для здачі у DOC/DOCX/PDF готується з перевіреного REPORT.

## 7. Рівень 3 — infra

- [ ] Actions виконує `verify` з тестами, аналізатором і пакуванням на
  `ubuntu-latest`, `windows-latest`, `macos-latest`.
- [ ] Workflow публікує JAR кожної ОС як артефакт.
- [ ] `--version`: версія POM і номер збірки; локально, наприклад, `1.0.0+local`.
- [ ] Перевірено запуск JAR і `--version` у CI.
- [ ] Git-тег `v1.0.0` вказує на перевірений результат.
- [ ] REPORT містить посилання на успішний CI та артефакти.
- [ ] Додано описи ролей Розробник, Валідатор, Документатор, Рецензент.
